## 3. Adapter findings that affect the recording design

The inspected adapter accepts only `PostToolUse` and `Stop`, and ignores capture recursion. Its ID includes destination, thread and tool/turn invocation when available; absent invocation IDs fall back to random UUIDs. A destination change changes identity by design. Preserve these existing export IDs rather than repurposing them as local recording IDs.

The pure normalizer sets `occurredAt` from its `now` argument, normally the adapter invocation clock. Two normalizations of the same hook at different times produce the same ID but different timestamps. Existing spool/acknowledgement logic preserves the first queued event and suppresses resolved duplicates; this discovery does not claim that retry currently rewrites the queued timestamp. This time is **hook receipt**, not verified original tool execution time. `turn_id` and `tool_use_id` contribute to identity but are not retained as separate event fields. Tool inputs/outputs and `cwd` are excluded; the optional project label comes from configuration.

Consequently, current events can answer “a tool or turn completed and was reported around this time.” They cannot reconstruct what code changed, identify the user's task reliably, measure run duration, or explain where to resume. For the first useful timeline, combine application context and completion markers with an explicit recording intention/project label and optional manual note. Rich automatic reconstruction remains a later selected-evidence experiment.

The hook reference supplies `cwd`, model and turn/tool identifiers, but no guaranteed original occurrence timestamp for these hooks. Subagent hooks can carry the parent session ID; do not call it a unique run ID. Hosted and specialized tool paths may be absent, and asynchronous handlers may arrive out of order or be cancelled. Adding start/subagent/interrupt hooks or retaining more fields is separate adapter work, not part of this pass. [Official hooks](https://learn.chatgpt.com/docs/hooks).

The existing spool is delivery state, not the local timeline: accepted payloads are removed in favor of acknowledgement records, queues are destination-scoped, and capture invokes delivery after enqueue. Copying that spool into a history UI would lose accepted detail and conflate upload scope with recording ownership.

## 4. Confirmed product decisions

The user confirmed all three choices on September 12, 2026: independent local recording, suspension with explicit resume after restart, and the minimal signal set. These decisions establish the implementation contract; they do not activate collection or grant OS permissions.

1. **Owner — confirmed:** explicit “Start recording” creates a durable local recording, independent of cloud Focus and the shared stopwatch. A Focus link is optional and records its backend/account scope. Local creation works while signed out or offline.
2. **Interruption policy — confirmed:** explicit Pause always requires Resume. Lock/sleep suspend collection; after a verified return, automatic resumption is allowed only if recording intent was active and no manual pause, permission loss, or storage failure occurred. Crash/relaunch always restores an interrupted recording requiring explicit Resume.
3. **Initial scope — confirmed:** foreground application transitions, lifecycle gaps and agent completion metadata; no title/path/URL/pixels/transcript text. Idle is a measured candidate, not selected as a behavioral threshold yet. Explicit user-entered intention/project/note supplies meaningful context.

Proposed retention for the synthetic proof: keep local history until explicit deletion; do not silently evict the only committed copy on storage pressure or sign-out. Real metadata retention duration and deletion/disclosure behavior remain to be settled before persistent personal capture. Encryption is deferred under the current task instruction; the first dependency-free SQLite proof is not an encrypted vault. No claim is made that sandbox storage substitutes for the longer-term security design.

## 5. State and correlation contract

This is the Task 2 design handoff using the confirmed choices above. It does not migrate the existing cloud Focus model or shared stopwatch.

| State / action | Local behavior | Evidence and UI consequence |
| --- | --- | --- |
| Ready → Start | Commit recording identity, intention, selected signal policy and first boundary; subscribe only after success. | Show recording only after the transaction succeeds; until a collector's first valid sample, its coverage is not established. |
| Recording → Work | Append observations through one serialized repository owner. Stamp source, time basis, stable identity and current interval/generation. | Application exposure and agent events may overlap. Neither is automatically focused human time. |
| Recording → Pause | Immediately stop/invalidate collectors, then commit the pause boundary with a stable command ID. | Subsequent machine observations are excluded. If saving fails, show stopped/unsaved and retry the same boundary; do not show “saved.” |
| Paused → Resume | Commit a new interval, then obtain a fresh foreground snapshot and subscribe. | Do not extend the previous app interval across the pause. |
| Sleep / session unavailable / permission lost | Stop the affected collector and record a coverage gap where storage is available. | No invented activity during the gap. Lock-specific detection remains a live-collection gate. Apply the selected resumption policy. |
| Storage unavailable | Stop collection, preserve prior committed history, report the failed boundary/event. | Do not switch to an apparently successful memory-only recorder. Corrupt/newer-schema stores need an explicit recovery path, not recreation. |
| Finish | Stop collectors, commit the final boundary/state, retain history. | Review committed evidence; local save and optional future upload acknowledgement are separate. Manual notes remain distinct from observations. |
| Relaunch | Load committed records; reconcile an unfinished recording as interrupted. | Never start collectors from restored state alone. Unknown crash time stays unknown; do not stretch the last observed app to the relaunch time. |
| Offline / expired cloud auth | Continue permitted local recording within its immutable local scope. | Cloud association/upload stays unavailable; no reassignment or deletion of local data on auth changes. |

Minimal identities/fields, without inventing a universal provider schema:

- `localScopeID` identifies the selected local workspace within the macOS user container. `recordingID` is a fresh UUID; `intervalID` identifies each start/resume interval. Allow at most one machine recording at a time. Switching local workspace stops the old recording before another starts. Cloud account changes never retarget committed observations or queued exports.
- An immutable local `eventID`, schema version, per-recording commit sequence, event kind, source and provenance class (`observed`, `agentReported`, `userNote`; inference stored separately). Duplicate identity plus identical payload is a no-op; conflicting payload is visible, not overwritten.
- `observedAt` is receiver wall time; optional source `occurredAt` carries an explicit `timeBasis` such as `sourceReported` or `hookReceived`. Use monotonic time for same-process elapsed intervals, paired with a process/boot marker; never compare uptime across restart as a wall timestamp. Store boundaries in UTC and render review days in an explicit timezone.
- Optional harness thread/turn/tool IDs and original export ID. Capture `recordingID`/`intervalID` at trusted intake; do not attach a delayed event to whichever recording happens to be active when it flushes. Backend account/session scope and delivery acknowledgement remain separate fields/records.
- Late events may be retained only with a previously established association and a trustworthy time basis within an authorized interval. The current async hook cannot establish original execution time; boundary ambiguity stays uncorrelated or is explicitly annotated. Re-ingestion does not manufacture a new event time.

## 6. Concrete Task 2 implementation handoff

**Ready to begin with synthetic events only.** Use GPT-5.6 Terra / High as the plan recommends. No dependency installation is required for the first storage spike: `import SQLite3` compiled and linked against the system library, reporting 3.51.0 on this Mac.

Add a small `RecordingRepository` boundary, a concrete system-SQLite adapter, and a recording model/service constructed once by `TimerAppComposition`. Keep AppKit observation on its appropriate executor and serialize blocking database operations away from the main actor. Owning an actor does not automatically make synchronous disk work harmless. A dedicated serial database owner is sufficient; no package split or replica engine is required.

For the initial single-process/single-connection proof, select rollback-journal mode with deliberate durable synchronization settings and verified foreign-key enforcement. Use parameter binding and versioned transactional migrations. Store under the app's own Application Support container, not in the existing Node spool. Recording transitions, canonical events and any maintained projection must commit atomically. [SQLite transactions](https://www.sqlite.org/transactional.html), [synchronization settings](https://www.sqlite.org/pragma.html#pragma_synchronous).

Do not enable concurrent WAL connections by default: SQLite documents a WAL-reset issue through 3.51.2, with a fix in 3.51.3 and selected backports. Apple's patch status is not proven by its 3.51.0 version string. The proposed single-connection rollback-journal slice avoids that WAL configuration; reconsider concurrency only with a verified library/build and a demonstrated need. [SQLite WAL documentation](https://www.sqlite.org/wal.html#walreset).

Task 2 acceptance must demonstrate:

1. Start → synthetic observations → pause → resume → finish → reopen reproduces committed history and projected intervals.
2. Forced termination of a disposable test process before/during/after commit yields either the full transaction or none; uncommitted state is never displayed as saved.
3. Stable command/event replay, conflicting duplicate identity, out-of-order delivery and an event racing Pause/Finish behave as specified.
4. A stale collector generation and a delayed event cannot enter a new interval/scope. Missing or ambiguous association remains explicit.
5. Migration success, interrupted migration, unsupported schema, missing/unwritable/full storage and bounded retry do not erase previous history or restart collection.
6. Relaunch restores “interrupted,” and explicit Resume creates a new interval. Offline/signed-out operation does not need backend acknowledgement. Auth expiry does not delete local canonical data.
7. Window close/reopen retains the same recorder and repository; ordinary app termination stops collectors. Existing Focus retry/account and stopwatch/widget tests still pass.
8. A fixture-backed review shows source, gaps and local save failure without inventing human focus time. Native live acceptance is recorded separately from tests.

Only after the synthetic proof and the remaining native lifecycle checks should Task 2 connect `NSWorkspace` app identity. Keep richer permissions disabled. Task 3 must separately choose and test a sandbox-compatible intake bridge for ordinary Codex hooks. Preserve the existing adapter and its queues; do not let an external harness write the recording database directly. A new hosted runtime, transcript scraping, global socket listener, or broad filesystem entitlement is not an implicit prerequisite.
