## Chosen path and trust boundary

A separately invoked Node helper owns a **new local-only outbox**. The sandboxed Mac app initiates authenticated HTTP pulls to an explicitly paired, literal `127.0.0.1` endpoint and owns all recording database writes. The helper never reads or writes the native database. The Mac app needs only its existing App Sandbox and outgoing-network entitlements. No incoming-network entitlement, app group, shared home-directory access, transcript reader, new dependency, or distribution change is required by this path.

Pairing is explicit: the native app creates and durably saves a random 256-bit capability and binding before displaying a pairing bundle. The user supplies that bundle to the helper through stdin, not command arguments or repository configuration. Production pairing/configuration is C3b, not installed here. Each binding names a stable sender installation, exact Codex thread, local scope, recording and interval, issue time, and acceptance deadline. Creation requires that exact interval to be active; Resume needs a new binding. The deadline is seven days from issuance for new events. Native-owned revocation stops all intake for that binding, including acknowledgements of previous events.

Sender trust means possession of the paired capability, not proof that an executable is OpenAI-signed, that a human worked, or that the reported result is true. Local root, compromised same-user processes, or a stolen capability are outside this trust boundary. HTTP is loopback-only, not encrypted storage or protection against local privileged inspection. Keys remain in private native/helper state and are never sent as HTTP bearer headers, put into observations, or logged. A sender-provided key, scope, or binding cannot establish trust.

The selected hooks are `PostToolUse` and `Stop`. Current official documentation supplies thread, turn and tool-call identifiers but no guaranteed original occurrence timestamp for these hooks; subagent hooks may use the parent session ID. Hook coverage/cancellation remains a live acceptance concern. This contract does not claim a distinct subagent run identity or passive attachment to the desktop app. [OpenAI hook reference](https://learn.chatgpt.com/docs/hooks).

## Wire and persistence rules

| Concern | Contract |
| --- | --- |
| Envelope | Version 1 metadata, at most 8 KiB of decoded UTF-8 JSON. Wire packet is `{body, mac}`, both base64; cap total wire bytes at 16 KiB before decoding. Reject unknown metadata keys, versions, malformed/bounded IDs, noncanonical timestamps and content fields. Golden Node/Swift vector: [fixture.json](probes/c3a/fixture.json). |
| Authentication | HMAC-SHA256 over UTF-8 `wellspent-c3a-event\0` followed by the **exact body bytes**, using the receiver-owned binding key. Constant-time MAC verification. No JSON canonicalization assumption. Request and ACK use separate `wellspent-c3a-poll\0` and `wellspent-c3a-ack\0` domains. Do not send the key itself. |
| Transport | Native ephemeral URLSession, pinned literal loopback host/port; disable proxies, redirects, cookies and response caching. `POST /v1/poll` returns a bounded pending packet without deleting it. C3b poll body includes binding ID, fresh nonce and short-lived issue time; helper validates before returning metadata. `POST /v1/ack` carries the authenticated receipt. No broadcast/discovery or remote fallback. |
| Association | Every packet includes binding, sender, thread, local scope, recording and interval IDs. Compare all with previously issued native pairing state and current committed recording history. No matching by foreground app, overlapping timestamps, cloud Focus session, or whichever recording is current at flush time. Unassociated input is excluded with a content-free visible reason; it is never silently rebound. |
| Event identity | SHA-256 of NUL-separated `wellspent-local-codex-v1`, sender ID, thread ID, hook kind, invocation ID; take first 16 bytes, set byte 6 high nibble to `8`, byte 8 high nibble to `a`, encode UUID. `tool_use_id` for tools; `turn_id` for Stop. No random fallback for missing IDs. Changing recording/binding or time does not create another identity for the same invocation. This is a new local namespace, not a change to existing cloud IDs. |
| Time | `hookReceivedAt` is the adapter's first receipt time in canonical UTC ISO milliseconds. `occurredAt` is **null** and `timeBasis` is `hookReceived` for this version. Reject invented occurrence timestamps. Native `RecordingEvent.stamp` is the first successfully committed native receipt, with its own wall time, uptime and process marker. ACK `nativeReceivedAt` is UTC ISO milliseconds. Never compare uptime across processes or infer execution duration. |
| Coverage | Eligibility uses the explicitly associated **hook receipt**, not unobserved execution time: `max(interval.start, binding.issuedAt) <= hookReceivedAt < interval.end`, with hook receipt no later than native receipt. Open interval returns retryable `awaitingIntervalEnd`; new reports commit only after a known pause/suspend/finish end. Reports appear after that boundary. Backward/ambiguous wall coverage fails closed. The timestamp remains a sender claim. |
| Interruption | Unknown crash/quit coverage is rejected as `interruptedInterval`; a later Resume does not repair or reassign it. Recovered open intervals must be interrupted before polling resumes. A previously committed exact duplicate can still receive its original ACK, without adding coverage. |
| Commit and ACK | Only return an authenticated receipt after native `repository.commit` succeeds. Receipt contains event UUID, SHA-256 of exact body bytes and original native receipt time. On retry, compare exact stored metadata bytes and commit the original event again before acknowledging. Changed payload with the same UUID is `identityConflict`; preserve the original. Concurrent deliveries converge through SQLite's transaction/unique identity boundary. |
| Sender retry | Persist first normalized packet with private permissions, file fsync, atomic first-writer publication and directory fsync before treating capture as queued. Retry those bytes; never re-normalize delivery timestamps. Retain pending data while helper/native are offline or ACK is absent/untrusted/mismatched. After a verified ID+body-digest ACK, durably publish a content-free ID receipt before deleting pending bytes. Recovery ignores unpublished temporary files. |
| Rejection | Invalid trust/schema/association, expired new input, out-of-interval times and interrupted coverage receive no success ACK. C3b retains already-normalized local packets in bounded quarantine with reason; missing association retains only a count/reason, not raw hook content. Retryable storage/offline/open-interval failures stay pending. Explicit deletion revokes that recording's bindings, preventing resurrection. Exact committed duplicates may be acknowledged after the new-event deadline, but never after revocation. |
| Privacy | Allowlisted opaque IDs, hook/tool kind and name, reported result enum, separate timestamps. No prompt, assistant prose, tool input/output, cwd, transcript path, URL, document/window content or token. `success` always means **reported**, not verified completion. New detailed observations stay local; no bridge to upload APIs. |

The prototype stores exact metadata bytes in the existing synthetic event's `text` field and maps hook receipt to the existing `sourceReported` timestamp. This is intentionally confined to the test target. **C3b must promote this to optional typed agent metadata with an explicit hook-receipt label**, retaining the original event schema's backward decoding and immutable identity. Base64 text is not the production timeline format.

Add bounded queue/quarantine status and explicit cleanup; extend self-capture exclusion to the new local commands. Enforce body/queue limits before publication and reads.
2. Implement explicit native pairing/binding issuance, durable native-owned key/binding/revocation state and helper stdin setup. Preserve sender identity across re-pairing, issue a new binding on each selected interval, prohibit retroactive binding, and fail closed if native state cannot be recovered. Keys/configuration require durable private publication, not the test fixture's convenience write. Serialize revocation/deletion with intake commits. Show paired thread, recording/interval and local-only disclosure. Do not use a global “current session” environment variable as correlation.
3. Run focused capture/native checks, then prepare one selected ordinary Codex session. **User hands-on testing resumes here**, with explicit authorization for the exact metadata-only local hook/configuration.
